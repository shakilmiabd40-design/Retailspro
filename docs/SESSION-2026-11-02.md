## 2. Mid-morning (08:47 – 08:48) — double-entry General Ledger design

Five files created/edited in a two-minute window, then **staged and never committed**
(still staged today, 443 insertions).

### New files

- `src/lib/accounting/gl-types.ts` — the domain model
  - `AccountType` / `NormalBalance` / `JournalStatus` / `PeriodStatus`
  - `ChartOfAccount` (code, type, normal balance, parent, `controlAccount`,
    `allowManual`, `isSystem`, `archived`)
  - `JournalEntry` + `JournalLine` — sources: `manual`, `po_receipt`,
    `supplier_invoice`, `sale`, `pos_sale`, `return`, `stock_adjustment`,
    `transfer`, `reversal`, `system`; statuses draft → posted → reversed
  - `InventoryMovement`, `InventoryCostLayer` (FIFO layers + landed cost),
    `StockAdjustment` (draft → pending_approval → approved → posted / rejected)
  - `GrniEntry` (Goods Received Not Invoiced, open → partial → invoiced → closed)
  - `ApInvoice` (BDT, tax/freight/other charges, GRNI links)
  - `AccountingPeriod` (open / closed / locked, with close + reopen audit fields)
  - `DEFAULT_COA` — 29-account chart: 1000 Assets, 2000 Liabilities,
    3000 Equity, 4000 Revenue, 5000 COGS, 6000 OpEx. Notable accounts:
    `1030` Mobile Banking (bKash/Nagad), `1300` GRNI, `5020` Purchase Price
    Variance, `5100` Inventory Adjustments / Shrinkage, `6040` Courier & Delivery.

- `src/lib/accounting/gl-store.tsx` — `GLProvider` + `useGL()`
  - Wires eight sync collections: `chart_of_accounts`, `journal_entries`,
    `inventory_movements`, `inventory_cost_layers`, `stock_adjustments`,
    `grni`, `ap_invoices`, `accounting_periods`
  - Seeds `DEFAULT_COA` on first run and resolves parent links by code
  - `addJournalEntry(input, post?)` — permission-gated, balances Dr/Cr to ±0.01,
    rejects zero-value journals, auto-numbers `JE-000001`
  - `postJournalEntry(id)` — requires `accounting.approve`; draft-only
  - `reverseJournalEntry(id, date, narration)` — swaps Dr/Cr, links both entries
  - `trialBalance(asOf?)` — posted entries only, with an as-of date cutoff
  - Every mutation writes an audit log entry

### Edited files

- `src/server/collections-names.ts` — added 9 collections:
  `chart_of_accounts`, `journal_entries`, `grni`, `ap_invoices`, `ar_invoices`,
  `inventory_movements`, `stock_adjustments`, `inventory_cost_layers`,
  `accounting_periods`
- `src/server/collections.ts` — per-role access rules for each. Deliberate split:
  read is broad (accounting / reports / inventory / purchase), write is narrow
  (accounting only, plus the module that owns the document). `grni` and
  `inventory_cost_layers` let purchase/inventory write; `ar_invoices` lets
  orders write.
- `prisma.config.ts` — `@prisma/orm-postgres` config targeting Postgres with
  `DATABASE_URL` (this was created 1 Nov, re-staged on 2 Nov)

### Status

`GLProvider` / `useGL` are **not imported anywhere yet**. The store exists but is
not mounted, so no screen uses it. That is the obvious next step.
